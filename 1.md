# Business Logic: The 3-Path Workflow
The app opens to a Role selector (`User` / `Company`). When `User` is selected, the stall owner can capture a lead using one of three flows:

### Path 1: Card with Information + Photo
1. **Capture:** Stall owner snaps a photo of the visitor's ID/Visiting card.
2. **Processing:** The frontend calls a Next.js backend API. 
   - The backend runs `Promise.all` to concurrently: 
     a) Send the image to Gemini API with a strict JSON schema prompt to extract data AND return `face_detected: true`.
     b) Upload the full card image to Google Drive, returning the `webViewLink`.
3. **Preview & Typewriter:** The frontend receives the data. It uses a clean, staggered Typewriter effect to auto-fill an editable form (Name, Age, Mobile, Email, Address, Gender, Company).
4. **Save:** The stall owner reviews/edits the form. Clicking "Save" appends the final form data + the generated Drive link to Google Sheets.

### Path 2: No Card (Manual Entry + Live Photo) - *Zero AI Usage*
1. **Capture:** Stall owner clicks "Manual Entry". An empty form appears.
2. **Input:** Stall owner types the data manually. Below the form is a "Capture Visitor Photo" button to snap a live photo.
3. **Save:** On clicking "Save", the frontend sends the data + photo to the backend. The backend uploads the live photo to Google Drive, gets the link, and appends the manual data + Drive link to Google Sheets. No AI APIs are called.

### Path 3: Card with Information, but NO Photo
1. **Capture:** Stall owner snaps a photo of the card.
2. **Processing:** Next.js backend sends the image to Gemini. Gemini extracts the JSON data and returns `face_detected: false`. (No Drive upload happens yet).
3. **Preview & Typewriter:** The frontend auto-fills the form using the typewriter effect. 
4. **Conditional Prompt:** Because `face_detected` is false, the frontend displays an alert: *"No photo detected on card. Please snap visitor face."* with a camera trigger.
5. **Save:** The stall owner snaps the live photo and reviews the text. Clicking "Save" sends the form data + live photo to the backend. The backend uploads the live photo to Drive and appends the data + Drive link to Sheets.

# UI/UX & Technical Constraints
1. **Typewriter Autofill Hook:** Write a custom React hook for the typewriter effect. The characters should stream into the input fields rapidly, but the input fields MUST remain standard controlled components so the user can easily click in and fix a typo immediately after the effect finishes.
2. **Google Sheets Schema:** The backend must append rows matching these exact columns: `Role | Name | Mobile | Email | Age | Gender | Address | Company | Photo_Drive_Link | Timestamp`.
3. **Null Handling:** Gemini must be instructed: "If a field is missing from the card, set its value to an empty string." The app must never crash on incomplete cards.
4. **Stateless API:** Do not use any local databases or Prisma. Vercel is stateless. Next.js API routes act purely as a bridge to Gemini, Drive, and Sheets.
